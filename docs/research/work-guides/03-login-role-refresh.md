# 03 · 로그인 역할 조회로 인한 서버 틱 대기 축소

**상태: PARTIAL.** 역할 조회 동시성·대기 경계를 구현하고 순수 Java로 검사했으며 1.21·26.2 대표 빌드가 성공했다. 실제 방장 서버 틱과 입장 정책은 아직 확인하지 않았다. 01·02와 독립된 작업이다.

- **기존 소스 확인:** 기준 커밋 `1880590`의 [`P2PBanManager`](../../../src/client/java/kfc/udp/client/webrtc/P2PBanManager.java)는 역할 조회 결과가 입장을 바꾸지 않는 경우에도 [`Roles.refreshBlocking`](../../../src/client/java/kfc/udp/client/webrtc/Roles.java)으로 최대 700ms 기다렸다. 정원이 찼을 때만 `hasPerk`가 만실 입장 허용에 쓰인다.
- **현재 구현:** 차단·추방·화이트리스트·IP 차단을 먼저 판정한다. 정원이 남으면 [`RoomRoles.ensureFreshForLogin`](../../../src/client/java/kfc/udp/client/webrtc/RoomRoles.java)이 조회를 비동기로 요청하고 서버 틱을 기다리지 않는다. 만실이면 이번 HTTP 요청에서 받은 서명 유효·파싱 완료 응답을 최대 700ms 기다린다. 실패·시간 초과에는 캐시에 남은 특혜로 정원을 우회하지 않고 만실로 거부한다. 따라서 역할 서버 장애 때 정상 특혜 사용자도 거부될 수 있다.
- **조회 수명:** [`RoleRefreshCoordinator`](../../../src/client/java/kfc/udp/client/webrtc/RoleRefreshCoordinator.java)는 진행 중 조회를 여러 로그인과 공유하고, 완료된 결과는 이후 만실 로그인에 재사용하지 않는다. 늦게 도착한 서명 유효 역할 변경은 현재 방장 세션과 서버를 다시 확인한 뒤 서버 스레드에서 방 상태·탭 배지를 갱신한다. 로비 조인 시 prefetch나 TTL 캐시 우회는 **구현하지 않았다**. 만실 특혜에 TTL 캐시를 적용하려면 별도 신뢰·만료 정책이 필요하다.
- **남은 신뢰 경계:** [`Roles`](../../../src/client/java/kfc/udp/client/webrtc/Roles.java)는 응답 서명을 확인하지만 nonce나 발급 시각을 확인하지 않는다. 이번 HTTP 요청의 응답이라도 서버 또는 전송 경로에서 과거의 정상 서명 본문을 재생한다면 이를 구별하지 못한다. 요청별 nonce·서명된 발급 시각·서버 보존 기간은 후속 프로토콜 작업으로 설계하고 서버 측 지원을 확인해야 한다.
- **순수 Java 검사:** [`RoleRefreshCheck`](../../../tools/tests/java/kfc/udp/client/webrtc/RoleRefreshCheck.java)는 진행 중 조회 합치기, 완료 후 새 조회, 실패, 시간 초과, 늦은 변경 알림, 변경 없는 검증 응답을 제어된 executor로 검사한다. 실제 HTTP 서명 검증, Minecraft 정책 연결, 서버 틱 시간, 탭 표시를 검사하지는 않는다.
- **대표 빌드 확인:** 현재 변경을 포함한 개발 체크아웃에서 JDK 25·Gradle 9.7.1의 `:1.21:build`와 `:26.2:build`가 `--configure-on-demand --offline --no-daemon`으로 성공했다. [공통 기록](README.md)에 시간과 경고를 적었다. 이 결과로 서버 틱과 실제 만실 판정은 검증되지 않는다. 현재 변경의 전체 17개 대상 빌드는 미실행이다.
- **실행 게이트:** 아래 조합에서 방장·게스트 두 인스턴스로 입장 결과와 서버 틱 시간을 기록한다. 역할 변경 후 방 상태·탭 배지도 확인한다.

  | 방 상태 | 역할 응답 | 기대 판정 |
  |---|---|---|
  | 정원 남음 | 성공·지연·실패 | 로컬 거부 조건을 통과했다면 역할 조회를 기다리지 않고 입장 |
  | 만실 | 이번 요청의 서명 유효 응답에 특혜 있음 | 700ms 안에 응답하면 입장. 응답 재생 가능성은 별도 검증 |
  | 만실 | 검증된 특혜 없음 | 만실 거부 |
  | 만실 | 실패·서명 오류·700ms 초과 | 캐시 특혜와 관계없이 만실 거부 |

- **되돌리기:** 역할 조정기, `Roles`·`RoomRoles` 호출, `P2PBanManager` 판정을 한 변경 단위로 되돌린다. 특히 서버 장애 때 만실 특혜 사용자를 거부하는 정책을 배포 전에 운영 기준으로 확인한다.
