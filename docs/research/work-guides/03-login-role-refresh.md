# 03 · 로그인 역할 조회로 인한 서버 틱 대기 축소

**상태: PLANNED.** 이 브랜치는 01·02만 구현한다. 역할 조회 변경은 별도 실험 브랜치에서 검토했으며, 이 체크아웃의 구현·검사·빌드 결과로 취급하지 않는다.

- **기존 소스 확인:** 기준 커밋 `1880590`의 [`P2PBanManager`](../../../src/client/java/kfc/udp/client/webrtc/P2PBanManager.java)는 역할 조회 결과가 입장을 바꾸지 않는 경우에도 [`Roles.refreshBlocking`](../../../src/client/java/kfc/udp/client/webrtc/Roles.java)으로 최대 700ms 기다렸다. 정원이 찼을 때만 `hasPerk`가 만실 입장 허용에 쓰인다. 현재 HEAD에서 이 경로를 다시 확인해야 한다.
- **설계 경계:** 차단·추방·화이트리스트·IP 차단은 역할 조회 전에 호스트가 판정한다. 정원이 남으면 조회를 비동기로 요청해 서버 틱을 기다리지 않는 방안을 검토한다. 만실이면 이번 요청에 대응하는 검증된 역할 응답을 제한 시간 안에 받았을 때만 특혜 입장을 허용한다. 실패·시간 초과에 캐시 특혜를 허용할지는 명시적인 신뢰 정책으로 결정한다.
- **조회 수명:** 진행 중 조회를 합치되, 완료된 응답을 뒤의 만실 입장에 무기한 재사용하지 않는다. 늦게 도착한 변경을 반영할 때 현재 방장 세션·서버 스레드를 확인한다. 로비 조인 prefetch와 TTL 캐시는 별도 설계다.
- **신뢰 경계:** 역할 응답 서명 확인과 별개로 nonce·발급 시각·만료 정책을 검토한다. 정상 서명 본문의 재생 가능성은 서버 프로토콜 지원 없이는 해결 여부를 단정할 수 없다.
- **검증 계획:** 제어된 executor로 동시 요청·실패·시간 초과·늦은 콜백을 검사한다. 1.21.x·26.x 대표 빌드와 두 클라이언트의 만실/비만실 입장, 서버 틱 시간, 방 상태·탭 배지를 각각 기록한다. 순수 Java 결과만으로 실제 Minecraft 입장 판정을 확정하지 않는다.

| 방 상태 | 역할 응답 | 확인할 판정 |
|---|---|---|
| 정원 남음 | 성공·지연·실패 | 로컬 거부 조건을 통과했다면 역할 조회를 기다리지 않고 입장 |
| 만실 | 이번 요청의 검증된 특혜 있음 | 정해진 제한 시간 안에 응답하면 입장 |
| 만실 | 검증된 특혜 없음 | 만실 거부 |
| 만실 | 실패·서명 오류·시간 초과 | 정한 신뢰 정책에 따라 일관되게 판정 |

- **되돌리기:** 역할 조회 조정기, 호출 경로, 만실 판정을 한 변경 단위로 되돌릴 수 있게 둔다. 서버 장애 때 특혜 사용자의 입장 정책을 배포 전에 정한다.
