# 04c · 월드 종료 대기를 배출 상태에 맞추기

**상태: PLANNED.** 마지막 Disconnect 패킷이 전달되는 현재 동작을 먼저 기록한다.

- **소스 확인:** [`KfcudpClient.kfcudp$delayedStopHost`](../../../src/client/java/kfc/udp/client/KfcudpClient.java)는 `waitForClose`가 참이면 고정 1.5초를 기다린다. 이 경로는 월드 종료 뒤 연결 정리를 위한 것이다.
- **추정:** 세션이 없는 경우의 시간 낭비는 코드상 명확하지만, 세션이 있을 때 최소 배출 시간은 실측하지 않았다.
- **제안·최소 변경:** 활성 세션이 없을 때만 즉시 종료한다. 다음 단계에서 writer 큐와 DataChannel `bufferedAmount`가 모두 비면 일찍 끝내고, 기존 1.5초는 상한으로 둔다.
- **정적 게이트:** 세션 수·큐·버퍼 관찰이 경쟁 상태에서 일관적인지, 종료 중 새 쓰기가 가능한지 확인한다. close/cancel 소유권은 그대로 둔다.
- **빌드 게이트:** 1.21.x·26.x 대표 빌드. 배출 상태를 순수 인터페이스로 분리했다면 경계값 계약 시험을 추가한다.
- **실행 게이트:** 게스트 0명·1명·여러 명, 정상 종료·강제 종료에서 종료 지연과 게스트 연결 해제 패킷을 확인한다. TURN 경로와 느린 링크도 별도 기록한다.
- **되돌리기:** 조건부 조기 종료를 제거하면 기존 1.5초 경로로 돌아가야 한다. 패킷 손실이 나오면 즉시 원복한다.
