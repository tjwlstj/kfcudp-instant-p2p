# 04b · 방장 네이티브 초기화를 렌더 스레드 밖으로

**상태: PLANNED.** 04a와 독립적이며, 먼저 첫 실행 시간을 재야 한다.

- **소스 확인:** [`KfcudpClient`](../../../src/client/java/kfc/udp/client/KfcudpClient.java)의 방 열기에서 [`WebRtcHost.start`](../../../src/client/java/kfc/udp/client/webrtc/WebRtcHost.java)가 `PeerConnectionFactory`를 만든다. 조사 문서는 webrtc-java 0.14.0의 라이브러리 추출·로드를 확인했다.
- **추정:** 실제 렌더 정지 시간과 Windows 임시 DLL 잔재는 사용 환경에서 아직 측정하지 않았다.
- **제안·최소 변경:** 방 설정 화면을 열 때 백그라운드에서 네이티브 로드를 선행한다. 방 열기에는 준비 완료·실패·취소의 명확한 상태를 두고 factory를 중복 생성하지 않는다. 로드 시간이 충분히 짧으면 이 변경을 미룬다.
- **정적 게이트:** factory와 executor 수명, UI 스레드 호출, 예외 전파와 재시도, 임시 파일 처리의 라이브러리 소유권을 검토한다.
- **빌드 게이트:** 1.21.x·26.x 대표 빌드. 버전별 네이티브 의존성 누락 여부를 확인한다.
- **실행 게이트:** 깨끗한 첫 실행과 두 번째 실행의 방 열기 지연을 측정한다. 설정 화면을 바로 닫거나 월드를 종료하는 경우도 확인하고, Windows 임시 폴더 관찰은 별도 기록으로 남긴다.
- **되돌리기:** 선로드 호출과 상태 대기만 제거해 기존 factory 생성 순서로 돌아간다. 라이브러리 내부 파일을 임의 삭제하지 않는다.
