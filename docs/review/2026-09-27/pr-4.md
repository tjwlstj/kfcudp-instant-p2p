## 확인한 점

- **순서:** 로컬 거부 조건을 먼저 판정하도록 옮겨서, 거부될 사람 때문에 네트워크를 타지 않는다.
- **스레드:**
  - 콜백은 `thenAcceptAsync(..., executor)`로 백그라운드에서 실행된다. 로그인 스레드에서 바로 실행되지 않는다.
  - `notifyChanged`는 잠금 안에서 콜백만 읽고, 실행은 잠금 밖에서 한다.
- **교착:** 조회와 완료 콜백이 같은 단일 스레드 실행기를 쓰지만, 그 실행기 안에서 서로를 기다리지 않는다. 대기(`get`)는 서버 스레드에서만 한다.
- **옛 방 보호:** 콜백은 `hostToken`과 현재 통합 서버를 다시 확인한 뒤 방송한다. 방을 새로 열거나 월드를 바꾼 뒤 늦게 도착한 응답이 엉뚱한 방에 적용되지 않는다.
- **검사:** `RoleRefreshCheck`가 결정적 실행기로 다음 경우를 검사하며 CI에서 통과한다.
  - 공유 조회와 늦은 콜백 등록
  - 조회 사이의 경쟁
  - 실패·시간 초과·무변화 응답
  - 콜백이 백그라운드 스레드에서 실행되는지
- **버전 분기:** 새 `isCurrentServer`는 1.21.x·26.x 분기 모두 있다.

## 남은 점

1. **만실 반복 시도의 대기**(발견 목록 [R20](findings.md#r20), 낮음)
   - 설계상 완료된 조회를 재사용하지 않으므로, 만실 로그인마다 새 HTTP 조회와 최대 0.7초의 서버 틱 대기가 생긴다.
   - 시그널링이 느리거나 죽어 있을 때 만실 방에 접속을 반복 시도하면 방장 틱이 반복해서 멈춘다. 시도하려면 WebRTC 연결까지 성사시켜야 하므로 비용은 있다.
   - 수 초짜리 검증 결과 유효 시간이나 플레이어별 재시도 간격을 검토한다.
2. **정책 변경 안내**
   - 역할 서비스가 응답하지 않으면 제작자·서포터도 만실 방에 들어가지 못한다.
   - 거부 문구는 일반 "방이 꽉 찼습니다"와 같다. 로그나 안내에서 "역할 확인 실패"를 구별할지 정한다.
3. **재생 공격 한계**
   - PR 문서에 적힌 대로, 평문 HTTP에서는 과거의 정상 서명 응답을 다시 보내는 공격을 막지 못한다.
   - 응답에 발급 시각이나 nonce를 넣으려면 서버 변경이 필요하다.
4. **병합 순서**
   - PR은 `beta`를 향한다. 지금은 `beta`와 `main`이 같은 커밋이다.
   - 이 검수 브랜치는 README 첫머리 한 줄만 바꾸므로 PR #4의 README 변경과 겹치지 않는다.
